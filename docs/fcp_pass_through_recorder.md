# FC Portugal pass-through transition recording

This stage is deliberately observational. The FC Portugal locomotion policy remains the authority for the action. RoboCOP records the transition produced by that action but does not modify it.

## Control flow

```text
FCP sensor frame S_t
        |
        v
FC Portugal Walk policy -----> baseline action A_t -----> robot/simulator
        |                              |
        |                              +---- copied, never modified
        v
RoboCOP pass-through recorder
        |
        v
transition = (S_t, A_t, S_t+1, outcome)
```

The directive returned by `FCPPassThroughRecorder.directive()` is always `pass_through` with `blend=0`. `observe_action()` returns the same numeric action values it received.

## What is stored

Each JSONL record contains:

- sensor frame before the FC Portugal action;
- the original FC Portugal baseline action;
- sensor frame after the action;
- reward/outcome when available;
- mean-square action energy proxy;
- terminal flag;
- source identifier.

Signed quantities are preserved. Roll, pitch and angular velocity therefore retain left/right and front/back direction instead of collapsing them to magnitudes.

## Research purpose

The first dataset should answer a narrower question than the earlier MuJoCo controller experiments:

> Which transitions generated by an already competitive locomotion policy reliably move the robot from a less stable state to a more stable state?

Only after this baseline has been recorded and characterized should a resolutive memory layer be allowed to intervene. The planned next stage is to index successful transitions by hierarchical state descriptors and test whether previously observed stabilizing transitions can be recognized online.

## Licensing boundary

The FC Portugal codebase remains an external GPL-3.0 dependency. This recorder operates on the license-neutral bridge representation in `robocop/fcp_protocol.py` and does not copy FC Portugal source into RoboCOP.

## Validation

The recorder tests cover:

1. exact pass-through of baseline actions;
2. preservation of signed sensor deltas;
3. JSON/JSONL round-trip persistence;
4. deterministic mean-square action energy proxy;
5. rejection of reversed timestamps;
6. aggregate recorder statistics.
